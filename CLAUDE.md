# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Daniele Bartorilla — Fotografia Naturalistica" — a single-page bird photography gallery (Vite + React 19), deployed to GitHub Pages by CI. All website text is in Italian; code, comments, and error messages are in English. No tests, no linter, no TypeScript; styling lives in `src/index.css` (design tokens as CSS variables, class-based styles) plus `src/lightbox.css`. Fonts (Cormorant Garamond + Inter) are self-hosted as woff2 under `public/fonts/`, preloaded in `index.html`. Page-view analytics via Umami (script tag in `index.html`), cookie-free — see `src/Policies.jsx`.

The page is: hero (the `hero: true` photo as background, in-page nav), gallery (responsive masonry with hover captions), "Chi sono" section, "Contatti" section, footer (with links to the privacy/cookie policy pages). The masonry columns are assigned in JS by greedy shortest-column packing (`distributeIntoColumns` in `Gallery.jsx`: each photo goes to whichever column has the least accumulated height so far, estimated from its aspect ratio; 3 columns above 1000px / 2 below, mirrored by CSS flex on `.gallery-grid`/`.gallery-column`, `align-items: flex-start` so flex doesn't stretch shorter columns to match the tallest), not via CSS `column-count`: since gallery order is shooting date (most recent first), a CSS-columns layout would fill column 1 top-to-bottom before starting column 2, burying recent photos instead of spreading them across the top row. A frosted-glass sticky nav (with back-to-top and scroll progress) appears once the hero is scrolled past; on mobile the nav links collapse into a hamburger that opens a side `NavDrawer`. The about-section portrait is optional: drop `src/profile.jpg` (or `.jpeg`/`.png`) and it is picked up via `import.meta.glob`; a placeholder shows otherwise. In-page nav must scroll programmatically (`scrollIntoView`), not via `#anchor` links, which would clash with the hash router.

## Commands

- `npm run dev` — start dev server on port 3000 (runs `generate-photos.js` first).
- `npm run build` — runs `node src/generate-photos.js`, `vite build`, then `node src/generate-social-pages.mjs` (post-build: per-photo Open Graph pages, see below).
- Deploy is automatic: every push to `main` triggers `.github/workflows/deploy.yml`, which builds and force-pushes `dist/` as a single orphan commit to the `deploy` branch (the GitHub Pages source for https://danibart.it). There is no manual deploy script.

## Photo pipeline (the key architecture)

Source JPGs live in `photos/` (committed). `src/generate-photos.js` uses sharp to produce `generated_photos/fullsize/` (quality 90 mozjpeg, progressive), `generated_photos/slides/` (1280px and 2048px renditions, `<name>-<width>.jpg` — combined with the fullsize into a per-slide `srcSet` in `photos.jsx` so the lightbox downloads a right-sized file instead of the multi-MB fullsize; the lightbox `slides` array in `Gallery.jsx` is hoisted to module scope on purpose — a new array identity each render makes yarl reset mid-swipe state), `generated_photos/original/` (quality 100 mozjpeg — opened in a new tab by the lightbox HQ button; re-encoded rather than copied so EXIF/GPS stays stripped), `generated_photos/thumbnails/` (600px wide, jpg + webp — gallery `<picture>` prefers webp), `generated_photos/hero/` (1920px wide, jpg + webp, only for `hero: true` entries), `generated_photos/social/` (1200px wide, for the Open Graph pages), and `generated_photos/metadata.json` (per photo: pixel dimensions, a tiny base64 blur-up placeholder used by the gallery and hero, the shooting date parsed from EXIF `DateTimeOriginal`/`DateTime` — used only to order the gallery, `null` if absent — and the rest of the shooting data parsed from EXIF via exif-reader — shown in the lightbox caption). `generated_photos/` is gitignored — it must be regenerated locally, and the app fails to show photos without it.

`photos.json` (repo root) is the single manifest: an array of `{filename, title, species, description}` entries (`species` is the optional Latin name, shown in the hover caption and lightbox; `description` may be empty and shows in the lightbox caption when set). Array order is gallery display order, but it's not hand-maintained: every run of `generate-photos.js` re-sorts it by each photo's EXIF shooting date, most recent first (undated photos keep their relative order and sort last), rewriting the file if the order changed. That same shooting date backs a "Nuova" glass badge on thumbnails less than 20 days old (`GalleryItem` in `Gallery.jsx`, computed client-side against `Date.now()` so it fades out on its own between deploys). One entry may carry `"hero": true` to become the hero background (falls back to the first entry). Alternatively, `"heroSmall": true` and `"heroLarge": true` (on different entries) pick distinct hero backgrounds for narrow vs wide viewports — the split happens at `(min-width: 1024px)` (`HERO_LARGE_QUERY` in `Gallery.jsx`, mirrored by the preload media queries in `generate-social-pages.mjs`); a missing variant falls back to the `hero: true` entry, then the first entry. The `heroLarge` photo also backs the site-wide Open Graph image. `src/photos.jsx` imports it and resolves URLs via `import.meta.glob`. **Adding a photo requires two steps:** drop the `.jpg` in `photos/` AND add an entry to `photos.json`. Each photo gets a stable URL id (URL-safe slug of `title` + MD5 of the filename), computed by `src/photo-id.mjs` — the single shared implementation; changing it breaks previously shared `/p/<id>/` links.

`src/generate-social-pages.mjs` (run by `build` after vite) writes a static `dist/p/<id>/index.html` per photo with Open Graph tags (pointing at `dist/social/`) plus a redirect to the SPA deep link, and injects into `dist/index.html` the site-wide Open Graph tags and a `<link rel="preload">` for the hashed hero webp (the LCP). The lightbox share button hands out these `/p/<id>/` URLs so shared links unfurl with the photo (in dev, where the `/p/` stubs don't exist, it falls back to the `/#/?photo=<id>` deep link); ids come from the shared `src/photo-id.mjs`.

`src/generate-photos.js` (run by both `dev` and `build`) reconciles `photos/*.jpg` with `photos.json`: a `.jpg` with no manifest entry aborts with a nonzero exit (the entry needs hand-written title/species), while a manifest entry whose `.jpg` was deleted is pruned from `photos.json` automatically — removing a photo only takes deleting the file. Generation is incremental (skips existing outputs) and deletes stale outputs whose source photo was removed.
## Routing / lightbox

`App.jsx` uses a hash router (GitHub Pages compatibility) with three routes: `/` renders `Gallery.jsx`, `/privacy` and `/cookie` render the legal pages in `src/Policies.jsx`. The lightbox (yet-another-react-lightbox with Zoom + Captions plugins) is driven by the `?photo=<id>` query param, so individual photos are deep-linkable; navigation within the lightbox rewrites the param with `replace: true`. The footer lives outside `RouterProvider`, so its links to the legal pages are plain `#/privacy` / `#/cookie` hash links rather than `<Link>`.
