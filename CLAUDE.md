# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Daniele Bartorilla — Fotografia Naturalistica" — a single-page bird photography gallery (Vite + React 19), deployed to GitHub Pages by CI. The site is bilingual, Italian and English — see "Languages" below; code, comments, and error messages are in English. No tests, no linter, no TypeScript; styling lives in `src/index.css` (design tokens as CSS variables, class-based styles) plus `src/lightbox.css`. The site has a light and a dark theme — see "Theming" below. Fonts (Cormorant Garamond + Inter) are self-hosted as woff2 under `public/fonts/`, preloaded in `index.html`. Page-view analytics via Umami (script tag in `index.html`), cookie-free — see `src/Policies.jsx`.

The main page is: hero (the `hero: true` photo as background, in-page nav), "Scatto della settimana", gallery (responsive masonry with hover captions, species + year filter chips), "Chi sono" section, "Contatti" section, footer. Two further routes hang off the nav: `/specie` (species index) and `/numeri` (stats from the EXIF data). Every chart on `/numeri` ends up horizontal below 600px — one labelled row per bucket, since twenty-odd columns across a phone are too narrow to label at all. The column charts flip in CSS alone, on the same markup, which is why `Columns` in `Stats.jsx` passes each bar's extent as a `--fill` custom property instead of an inline height: the mobile rules read the same number as a width. The masonry columns are assigned in JS by greedy shortest-column packing (`distributeIntoColumns` in `Gallery.jsx`: each photo goes to whichever column has the least accumulated height so far, estimated from its aspect ratio; 3 columns above 1000px / 2 below, mirrored by CSS flex on `.gallery-grid`/`.gallery-column`, `align-items: flex-start` so flex doesn't stretch shorter columns to match the tallest), not via CSS `column-count`: since gallery order is shooting date (most recent first), a CSS-columns layout would fill column 1 top-to-bottom before starting column 2, burying recent photos instead of spreading them across the top row. A frosted-glass sticky nav (with back-to-top and scroll progress) appears once the hero is scrolled past; on mobile the nav links collapse into a hamburger that opens a side `NavDrawer`. The about-section portrait is optional: drop `src/profile.jpg` (or `.jpeg`/`.png`) and it is picked up via `import.meta.glob`; a placeholder shows otherwise. In-page nav must scroll programmatically (`scrollIntoView`), not via `#anchor` links, which would clash with the hash router.

## Commands

- `npm run dev` — start dev server on port 3000 (runs `generate-photos.js` first).
- `npm run build` — runs `node src/generate-photos.js`, `vite build`, then `node src/generate-static-pages.mjs` (post-build: the static HTML surface, see below).
- Deploy is automatic: every push to `main` triggers `.github/workflows/deploy.yml`, which builds and force-pushes `dist/` as a single orphan commit to the `deploy` branch (the GitHub Pages source for https://danibart.it). There is no manual deploy script.

## Photo pipeline (the key architecture)

Source JPGs live in `photos/` (committed). `src/generate-photos.js` uses sharp to produce `generated_photos/fullsize/` (quality 90 mozjpeg, progressive), `generated_photos/slides/` (1280px and 2048px renditions, `<name>-<width>.jpg` — combined with the fullsize into a per-slide `srcSet` in `photos.jsx` so the lightbox downloads a right-sized file instead of the multi-MB fullsize; the `slides` array in `Gallery.jsx` is built by a module-scope `toSlide` and memoized on the filtered photo list, because a new array identity mid-swipe makes yarl reset its state — it must change only when the filters do), `generated_photos/original/` (quality 100 mozjpeg — opened in a new tab by the lightbox HQ button; re-encoded rather than copied so EXIF/GPS stays stripped), `generated_photos/thumbnails/` (600px wide, jpg + webp + avif — gallery `<picture>` prefers avif, then webp), `generated_photos/hero/` (1920px wide, jpg + webp + avif, only for `hero: true` entries), `generated_photos/social/` (1200px wide, for the static pages and Open Graph), and `generated_photos/metadata.json` (per photo: pixel dimensions, a tiny base64 blur-up placeholder used by the gallery and hero, the shooting date parsed from EXIF `DateTimeOriginal`/`DateTime` — used only to order the gallery, `null` if absent — and the rest of the shooting data parsed from EXIF via exif-reader — shown in the lightbox caption). `generated_photos/` is gitignored — it must be regenerated locally, and the app fails to show photos without it.

`photos.json` (repo root) is the single manifest: an array of `{filename, title, species, description, position}` entries (`species` is the optional Latin name, shown in the hover caption and lightbox; `description` may be empty and shows in the lightbox caption when set; `position` is where the shot was taken, normally just the region — "Lombardia" — and drives the little map on the photo page and the one on `/numeri`, see "Regions" below). The Italian text is the original; `titleEn`, `descriptionEn` and `positionEn` are the optional English counterparts, and anything missing falls back to the Italian (`photoTitle`/`photoDescription` in `src/i18n.mjs`, `positionLabel` in `regions.mjs`) — a photo can be added untranslated without leaving a blank caption. `title` alone backs the URL id, so translating one never moves a page. Array order is gallery display order, but it's not hand-maintained: every run of `generate-photos.js` re-sorts it by each photo's EXIF shooting date, most recent first (undated photos keep their relative order and sort last), rewriting the file if the order changed. That same shooting date backs a "Nuova" glass badge on thumbnails less than 20 days old (`GalleryItem` in `Gallery.jsx`, computed client-side against `Date.now()` so it fades out on its own between deploys). One entry may carry `"hero": true` to become the hero background (falls back to the first entry). Alternatively, `"heroSmall": true` and `"heroLarge": true` (on different entries) pick distinct hero backgrounds for narrow vs wide viewports — the split happens at `(min-width: 1024px)` (`HERO_LARGE_QUERY` in `Gallery.jsx`, mirrored by the preload media queries in `generate-static-pages.mjs`); a missing variant falls back to the `hero: true` entry, then the first entry. The `heroLarge` photo also backs the site-wide Open Graph image. `src/photos.jsx` imports it and resolves URLs via `import.meta.glob`. **Adding a photo requires two steps:** drop the `.jpg` in `photos/` AND add an entry to `photos.json`. Each photo gets a stable URL id (URL-safe slug of `title` + MD5 of the filename), computed by `src/photo-id.mjs` — the single shared implementation; changing it breaks previously shared `/p/<id>/` links.

## Theming

Colours come in pairs: `:root` in `src/index.css` holds the dark palette as raw channels (`--bg-rgb`, `--text-rgb`, …) plus the solid tokens derived from them (`--bg: rgb(var(--bg-rgb))`). A theme therefore only restates the six channel lines and the solid tokens re-resolve. Anything needing transparency writes `rgb(var(--x-rgb) / 0.3)` — **no bare `rgba()` with literal channels**, or it will not follow the theme.

- **Three states, two stored.** No stored preference means "follow the device", handled purely by `@media (prefers-color-scheme: light)`. The sun/moon toggle pins `data-theme` on `<html>` and writes `theme` into localStorage; picking the theme the device already uses *clears* the override instead of pinning it. `src/theme.mjs` owns this, and `index.html` carries a copy of the read half as a pre-paint inline script so an overridden page never flashes the wrong theme. `generate-static-pages.mjs` inlines its own copy (`THEME_BOOT` / `THEME_SCRIPT`) because the static pages load no bundle.
- **The light palette is written twice** (once under `:root[data-theme="light"]`, once inside the media query). Plain CSS cannot share one block between the two, and `light-dark()` needs Safari 17.5 while `cssTarget` is still safari15.
- **Restating the channels works at `:root`, not on a descendant.** `--bg`/`--surface`/`--accent` are declared once on `:root` as `rgb(var(--x-rgb))`, so they are *computed there* and inherit down already resolved. A theme block works because it restates the channels on `:root` too. An element deep in the tree that restates a channel only changes what usages **written on that element** resolve to — `background: rgb(var(--surface-rgb))` follows it, `background: var(--surface)` does not. The filmstrip in `lightbox.css` is the one place that does this, and it reads channels throughout for exactly this reason.
- **Anything painted on a photograph keeps the dark colours in both themes** — the hero content and nav, the gallery caption, the "Nuova" badge, the featured text, and the whole lightbox. What they contrast with is the photo, not the page. That rule restates the channel tokens *and* `color`: headings inside those containers declare no colour of their own, so they inherit the value already resolved on `<body>` and overriding the tokens alone never reaches them.
- The hero overlay is split for the same reason: the scrim that darkens the photo under the title is a constant dark, and only the fade joining the hero to the page below follows the theme. That join is a `--hero-join` custom property so the media query can swap it alone — eased over ~22% of the hero for `heroLarge`, ~38% below the 1024px breakpoint, where a short ramp banded visibly. The query mirrors `HERO_LARGE_QUERY` in `Gallery.jsx`.
- The light accent is a deeper bronze (`122 92 34`) — the dark theme's gold reaches only 1.9:1 on a light background.
- The Cookie Policy documents the localStorage entries (`theme` and `lang`). If either changes, that page has to change with it.

## Languages

Italian and English. Italian is the original — `photos.json` is written in it, the canonical URLs are derived from it, and it is what any missing English string falls back to.

- **`src/i18n.mjs` holds every user-facing string**, as two flat objects (`IT` / `EN`) reached through `strings(lang)`. Parameterized entries are plain functions (`t.shots(3)`, `t.galleryCount(n, species, year)`) rather than format strings with placeholders, because plural agreement and word order diverge too far between the two for one template to serve both. It imports nothing — `generate-static-pages.mjs` runs it under Node. The React half is `src/lang.jsx`: one context at the root of `App.jsx`, exposing `{lang, t, switchLang}` through `useLang()`, which also keeps `<html lang>`, `document.title` and the meta description in step.
- **The two legal pages are the exception**: their prose lives in `Policies.jsx` as two whole bodies picked by `lang`. Stitching a legal text together out of dictionary fragments is exactly what a legal text must not be.
- **Same three states, two stored, as the theme.** No stored value means "follow the browser" (`navigator.languages`, anything Italian gets Italian and everyone else English); the toggle writes `lang` into localStorage, and picking the language the browser already asks for *clears* the override. `src/i18n.mjs` owns it, mirroring `theme.mjs` line for line.
- **The toggle is the theme toggle's twin** (`src/Toggles.jsx` holds both): the same circle, worded with the code of the language a click switches *to* — "EN" while the page is Italian — and its accessible name is written in that target language, since the visitor who needs the button is the one who cannot read the page. It sits next to the theme toggle in both navs, in the mobile drawer as a labelled pill, and — alone — in the `.subpage-top` row of every sub-page, which carries no nav bar of its own.
- **The SPA has no per-language URL.** Language is a stored preference like the theme, not part of the hash route, so nothing has to be kept in sync and every existing link keeps working. The static surface is the opposite: it is pre-rendered, so it needs two of everything (below).
- **Nothing that is baked into a URL is ever translated**: the photo id comes from the Italian `title`, `?specie=` carries the Italian slug in both languages, and `REGION_PATHS` is keyed by the Italian region name. Only labels change.

## Static HTML surface

The SPA renders entirely in JS, so everything a crawler or a link preview needs is emitted as plain HTML by `src/generate-static-pages.mjs` (run by `build` after vite), once per language: `dist/p/<id>/index.html` per photo (the photo, its species, description and shooting data, `ImageObject` JSON-LD, prev/next links, and a CTA into the gallery), `dist/s/<slug>/index.html` per species plus `dist/s/` as their index, the same three under `dist/en/`, and `dist/sitemap.xml` listing all of them. It also injects the site-wide Open Graph tags, the gallery JSON-LD and the hero preload into `dist/index.html`.

Two things to know before touching it:

- **English hangs off an `/en/` prefix; the Italian URLs are untouched.** Every page names both halves through `rel="alternate" hreflang` (plus `x-default` on the Italian one) and carries a switch to its counterpart in the header — an `<a href>`, not a button, so it works with the script blocked and gives a crawler a second path to the translation. `layout()` takes a `paths` map keyed by language and derives the canonical, the alternates and that switch from it, so the three can never disagree. `LANG_SCRIPT` only adds the "remember this" half, with the same store-only-if-it-differs rule as `setLang`. `dist/index.html` is the exception: the SPA is one URL for both languages, so it carries the Italian tags and names English only as `og:locale:alternate`.
- **The `/p/` pages are real pages, not redirects.** They used to bounce into the SPA deep link; a redirect is not indexable, and the static page paints the photo without the JS bundle. The lightbox share button hands out these URLs. Each gallery thumbnail also carries a real `<a href>` to its `/p/` page (`.gallery-link`, a transparent overlay that intercepts plain clicks to open the lightbox) — that anchor is the only path a crawler has from the home page into the photo pages.
- **Page titles are deduplicated, not templated.** Five photos are titled "Airone Cenerino"; `buildPageTitles` escalates a colliding group through progressively more specific labels (bare title → + date → + time → "n di m") until it breaks up, so unique titles stay plain and only real clashes get qualified. The last level is unique by construction — burst frames tie on everything else. It runs once per language: which titles collide is a property of the language, not of the manifest.
- **The Open Graph copy is published under a descriptive filename** (`social/airone-cenerino-<id>.jpg`, not `IMG_5893.jpg`), since the filename is one of the signals Google Images reads.
- **Hashed assets are matched by byte size.** vite flattens every rendition into `dist/assets/<basename>-<hash>.<ext>`, so a photo's thumbnail, full-size copy and quality-100 original all collide as `IMG_6501-<hash>.jpg`. `assetFor("fullsize/IMG_6501.jpg")` narrows by name prefix and then matches the exact file size against the source in `generated_photos/` — vite copies assets byte for byte. Do not try to parse the hash out of the filename: vite's hash alphabet includes `-`, so `IMG_6501-1280-<hash>.jpg` cannot be split back into stem and hash by pattern. A miss warns, except below vite's 4096-byte `assetsInlineLimit`, where the asset legitimately became a data URI in the bundle.
- **The `/p/` page is the lightbox's HQ destination**, so it serves the photo full-resolution: the `srcSet` tops out at the `fullsize` rendition and `sizes="100vw"` lets a retina or wide screen pick it. The frame's shape comes from an inline `aspect-ratio` plus a `max-width` capping it to 78vh, both computed at build time — the img cannot size the box itself before a multi-MB file arrives, and without it the page collapsed and jumped on load. The blurred `::before` under it is the same base64 placeholder the gallery uses.
- **These pages exist in dev too**, so HQ / share / the thumbnail anchors go to the same URL everywhere. `src/static-pages-dev.mjs` is a `apply: "serve"` vite plugin that runs the same generator with `STATIC_PAGES_DEV=1` and answers `/p/`, `/s/` and their `/en/` counterparts from its output (a 404 for an unknown id rather than vite's SPA fallback, which would silently answer with the gallery). In that mode the generator writes to `.dev-static/` (gitignored, wiped on each run), resolves assets to `/generated_photos/<rendition>/…` — unhashed, served by vite straight from the project root — drops the analytics tag, and stops before the build-only tail (`dist/index.html` injection, sitemap). The middleware is registered inside `configureServer` rather than in a returned callback so it runs *before* the SPA fallback, and it regenerates only when `photos.json`, `metadata.json` or the generator's own modules have a newer mtime. Production output is unaffected: it is byte-identical with the flag off.

`src/species.mjs` is the shared source of truth for species naming — Latin→Italian and Latin→English common names, the `·` splitting for multi-species entries, and the `/s/<slug>/` slugs — imported by both the React app and the generator. `speciesSlug` is always derived from the *Italian* name: it is the canonical id, carried by `?specie=` and by the Italian pages, so renaming a species there breaks its existing URL (same caveat as `photo-id.mjs`). `speciesSlugFor(latin, lang)` is what the English pages use for their own `/en/s/grey-heron/` URLs.

`src/generate-photos.js` (run by both `dev` and `build`) reconciles `photos/*.jpg` with `photos.json`: a `.jpg` with no manifest entry aborts with a nonzero exit (the entry needs hand-written title/species), while a manifest entry whose `.jpg` was deleted is pruned from `photos.json` automatically — removing a photo only takes deleting the file. Generation is incremental (skips existing outputs) and deletes stale outputs whose source photo was removed.

## Regions

`src/regions.mjs` does for `position` what `species.mjs` does for `species`: it holds an SVG path per Italian region plus `findRegion`, which maps a written position onto one of them (case, accents and apostrophes are normalised, a few alternate names are aliased, and a value like "Parco del Ticino, Lombardia" is matched on its comma-separated parts). It is drawn twice — as the card at the end of a `/p/` page ("Scattata in", region filled on a small map of Italy) and as the "Dove scatto" map on `/numeri`, where every region a photo comes from is filled, shaded by how many, alongside the same counts as bars.

- **The Italian name is the region's identity, in both languages**: it keys `REGION_PATHS`, it is what `findRegion` returns and what the per-region counts are grouped by. `regionName(region, lang)` translates only the label, and only for the handful English actually renames (Lombardia → Lombardy, Puglia → Apulia, …). `positionLabel(photo, lang)` handles the manifest field: a `position` that is nothing but a region name is translated outright, anything more specific ("Parco del Ticino, Lombardia") comes from an optional `positionEn` or is printed as written, since it is a proper name.
- **All twenty paths share one national projection and one `MAP_VIEWBOX`**, so a region path drawn over `ITALY_PATH` (the twenty outlines concatenated, used as the faint backdrop) lands exactly on its own outline. Two paths, no alignment maths.
- **The geometry is checked in, not generated at build time.** It comes from the Openpolis/ISTAT administrative boundaries, projected and simplified to ~3km — well under a pixel at the sizes it is shown — with minor islands dropped, since Lampedusa alone stretched Sicily's share of the map hundreds of kilometres south. Regenerating it is a one-off script; borders do not move.
- **A position no region matches is not an error**: the photo page falls back to a pin icon next to the text, and `/numeri` lists the place under the map without a bar. That is what a foreign trip would look like. A missing `position` simply drops the card.
- The map is inline SVG in both places (`.place-map` on `/p/`, `.region-map` on `/numeri`) rather than a file, so its colours are CSS tokens and follow the theme — an `<img>` could not.
- Only the region reaches the structured data (`contentLocation` on the photo page's `ImageObject`), never anything more precise. These are wild birds, which is the same reason `generate-photos.js` re-encodes every rendition to strip GPS out of the EXIF.

## Routing / lightbox

`App.jsx` uses a hash router (GitHub Pages compatibility): `/` renders `Gallery.jsx`, `/specie` the species index, `/numeri` the stats page (both wrapped in `src/SubPage.jsx`, which resets the scroll on mount), `/privacy` and `/cookie` the legal pages in `src/Policies.jsx`. The footer lives outside `RouterProvider`, so its links are plain `#/...` hash links rather than `<Link>`.

The gallery keeps all of its state in the query string — `?photo=<id>` for the lightbox, `?specie=<slug>` and `?anno=<year>` for the filters — so every view is linkable and there is no state/URL sync to maintain. Anything that navigates goes through `navigateWithParams`, which *merges* into the existing query string; replacing it outright would drop the filters on a swipe (or the open photo on a filter click). That helper reads the location from a ref rather than a dependency: it is passed to the memoized `GalleryItem`s, and a fresh identity per swipe would re-render all of them. Arriving at the gallery with a filter already in the query string scrolls straight to `#galleria` rather than the hero — a card on `/specie`, a bar on `/numeri` and a shared filtered link all mean "show me the filtered gallery". It is read once at mount (`enteredFiltered`), so working the filter chips, which re-render without remounting, never yanks the page; a `?photo=` link is excluded, since there the lightbox is the subject. The lightbox walks the *filtered* list, so arrowing out of a filter can't land on another species; a deep link to a photo the filters exclude falls back to the full list.

Plugins in use: Zoom, Thumbnails, Slideshow. yarl's labels are English by default, so the Italian ones are passed via `labels`. Toolbar buttons are a custom array — the `"slideshow"` string is a placeholder the plugin substitutes in place, and without it the button would be prepended instead. The Zoom plugin is kept for pinch/double-tap/wheel but its `+`/`−` buttons are dropped with `render.buttonZoom: () => null`. The lightbox is deliberately bare: no captions, no counter, no info button — just the photo, the filmstrip and slideshow / HQ / share / close. The HQ button leaves the SPA for the photo's `/p/` page.
